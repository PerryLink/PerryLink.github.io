这个插件核对什么

病案首页质控（dsh-medrec-qc）是一个面向医疗病案场景的 DeepSeek Harness 核查插件。病案首页形式质控与逻辑矛盾提示（依据国卫办医发〔2016〕24号等公开文件，仅提示差异，不作出定性结论）

15 条规则构成了本族里较完整的一套核对，落到的要素比多数插件更多。该规则库同时包含「条文直接规定」与「由原则推导」两类依据：前者 13 条，后者 2 条。

核对方式

从检查方式看，病案首页质控用的是几类可以机械判定的手段：。

这些检查都只读取材料本身的内容：不查外部数据库、不做联网核对、不调用模型判断，因此同一份材料在同样配置下每次得到的结果一致。

该规则库不涉及数值计算：它看的是要素齐不齐、取值在不在允许范围内、字段之间对不对得上。

它不作什么判断

共同约定只有一条——插件只做「指出不一致」，不做「下结论」。差异清单里每条都带规则编号、依据的文件与条款、以及差异落在材料里的位置。

本插件使用「错误」级严重度，共 9 条规则属于该级。这些规则所依据的条文都已取得逐字文本，只有在材料与条文明确不符时才会命中，也因此可以作为返工依据。

每个没能跑起来的检查都会出现在跳过项里并附上原因——缺字段、缺配置、或规则要求的前置项不存在。所以「没有差异」和「没有检查」在结果里是两件分开陈述的事。

严重度含义：错误（9 条）——规则所依据的条文已取得逐字文本，出现差异即为明确不符；提示（5 条）——差异成立，但条文未直接规定，或需人工判断后确认；参考（1 条）——只作提示，供人工复核，不构成任何结论。

依据类型含义：条文直接规定（13 条）——该规则的依据条文已取得逐字文本，规则直接对照条文规定；由原则推导（2 条）——未能取得逐字条文，依原则性条款推导，严重度上限为「提示」。

引用取证状态

引用取证：规则库没有遗留待取证条目。13 条规则直接对照条文；剩下的规则依据原则或本机构配置，不涉及条文原文，因此不存在取证进度问题。

规则库落在 4 份文件上，分布如下：《住院病案首页数据填写质量规范（暂行）》（8 条）、《卫生部关于修订住院病案首页的通知》（5 条）、《住院病案首页数据质量管理与控制指标（2016版）》（1 条）、国家医疗保障局"两库"知识点（诊断与患者性别不符）（1 条）。同一文件的不同条款会被多条规则分别引用，因此上面是文件层面的汇总。

结果怎么读

本插件共 15 条规则，其中严重度最高的一档是「错误」，共 9 条：MR-002、MR-003、MR-004、MR-005、MR-006、MR-007、MR-008、MR-009、MR-010。结果里先看这几条，再回头处理其他规则报出的差异。

适用场景与同组插件

面向病案室、质控科与临床科室的病历与编码核对：病案首页、护理记录、ICD 编码结构与星剑号配对。

同一职业分组「医疗病案」下还有 2 个核查插件，分别是ICD 编码规则校验（dsh-icd-rule-check）、护理记录时限、签名与评估表完整性校验（dsh-nurse-record-check）。这几个插件的范围彼此不重叠，也不会互相替代；要覆盖这类材料的全貌，需要挑出对应的几个分别跑。

npm 包名 dsh-medrec-qc，仓库 PerryLink/dsh-medrec-qc，Apache-2.0 许可。页面上的规则与依据由构建脚本从规则库（版本 2026.1）与包的 locale 资源读出，与仓库内容一致。

  • ICD 编码规则校验 dsh-icd-rule-check —— ICD 合并编码与星剑号配对提示
  • 护理记录时限、签名与评估表完整性校验 dsh-nurse-record-check —— 护理记录时限、签名与评估表完整性校验

安装

先在 bash 或 PowerShell 里装上，再确认配置里出现了这个包名：

bash / sh

dsh plugin --profile default add dsh-medrec-qc
dsh --profile default --dump-config | grep 'dsh-medrec-qc'

PowerShell

dsh plugin --profile default add dsh-medrec-qc
dsh --profile default --dump-config | Select-String 'dsh-medrec-qc'

把 --profile default 换成实际使用的 profile 名。装上之后重新启动会话，插件注册的工具才会出现。
