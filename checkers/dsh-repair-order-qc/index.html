这个插件核对什么

维修工单核对（dsh-repair-order-qc）是一个面向质量制造场景的 DeepSeek Harness 核查插件。维修工单结算核对（按项目金额、配件工时合计与结算总额核对算术自洽，仅提示差异，不作出定性结论）

规则库共 7 条规则，覆盖面与人工复核一遍的注意力分配大致相当。依据来源是混合的：「条文直接规定」4 条、「由原则推导」3 条。两类规则的证据强度不同，结果里的严重度已经反映了这个差别。

核对方式

维修工单核对的检查手段集中在以下几类，都不依赖模型判断：多字段至少填一（1 条）、乘积关系一致（1 条）、求和结果一致（1 条）、按公式重算并比对（1 条）、日期可解析（1 条）、编号或键不得重复（1 条）。此外还有 1 类出现频次较低的检查方式。

这些检查都只读取材料本身的内容：不查外部数据库、不做联网核对、不调用模型判断，因此同一份材料在同样配置下每次得到的结果一致。

它不作什么判断

共同约定只有一条——插件只做「指出不一致」，不做「下结论」。差异清单里每条都带规则编号、依据的文件与条款、以及差异落在材料里的位置。

结果里最高的严重度是「提示」。这不是保守，而是如实的：这些规则所对照的条文没有逐字文本，凭原则推导不足以支撑更强的结论。

规则库中未被命中的规则同样会出现在结果里：无法执行的检查会连同原因一起列出，空的结果列表不等于材料没有问题，只等于规则库覆盖到的那部分没有发现差异。

引用取证状态

引用取证：可以逐字对照条文的规则共 4 条，没有一条规则标注「本次未取得」。这意味着规则库对自身依据的声明是完整的：要么引用条文原文，要么明确说明依据并非条文。

规则引用的文件共 1 份，按引用规则数排列为：《机动车维修管理规定》（7 条）。同一份文件在不同规则中可能被引用于不同条款。

结果怎么读

本插件共 7 条规则，其中严重度最高的一档是「提示」，共 7 条：RO-001、RO-002、RO-003、RO-004、RO-005、RO-006、RO-007。这些规则命中时应当优先处理，其余规则的结果可以在其后逐条确认。

适用场景与同组插件

面向质量管理与工艺岗的体系文件核对：FMEA 分析表、PPAP 提交要素、SPC 控制图常数与过程能力、审核意见闭环。

同一职业分组「质量制造」下还有 7 个核查插件，分别是FMEA 表核对（dsh-fmea-table-check）、点评回复核对（dsh-ota-review-check）、项目链条核对（dsh-pipeline-check）、PPAP 要素核对（dsh-ppap-check）、审稿回应核对（dsh-review-reply-check）、控制图常数核对（dsh-spc-gbt-adapter） 等。实际使用中往往要跑不止一个：单个插件只负责它自己那份规则库声明过的范围，范围之间不重叠，合起来才接近一次完整复核。

发布渠道是 npm 包 dsh-repair-order-qc，源码在 GitHub 的 PerryLink/dsh-repair-order-qc，许可为 Apache-2.0。本页的规则清单直接取自仓库里的规则库文件（版本 2026.1），不是手写的介绍。

  • FMEA 表核对 dsh-fmea-table-check —— FMEA 分析表要素齐备性与风险顺序数一致性核对
  • 点评回复核对 dsh-ota-review-check —— 在线点评回复台账核对
  • 项目链条核对 dsh-pipeline-check —— 项目全流程文件链条核对
  • PPAP 要素核对 dsh-ppap-check —— PPAP 提交要素齐备性核对
  • 审稿回应核对 dsh-review-reply-check —— 审稿意见逐条回应覆盖核对
  • 控制图常数核对 dsh-spc-gbt-adapter —— 控制图常数与过程能力指数核对
  • 质保索赔核对 dsh-warranty-calc —— 质保期与索赔金额核对

安装

安装命令对两个平台是同一个 dsh 子命令，只有随后确认安装结果的那一步按 shell 不同：

bash / sh

dsh plugin --profile default add dsh-repair-order-qc
dsh --profile default --dump-config | grep 'dsh-repair-order-qc'

PowerShell

dsh plugin --profile default add dsh-repair-order-qc
dsh --profile default --dump-config | Select-String 'dsh-repair-order-qc'

把 --profile default 换成实际使用的 profile 名。装上之后重新启动会话，插件注册的工具才会出现。
