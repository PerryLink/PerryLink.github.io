这个插件核对什么

土壤地下水监测核对（dsh-soilwater-check）是一个面向工程建设场景的 DeepSeek Harness 核查插件。土壤与地下水监测台账核对（按点位、监测项目、限值与超标判定核对台账自洽，仅提示差异，不作出定性结论）

规则库 8 条规则，数量居中：既能覆盖这类材料的主要要素，又不会把无关项也拉进来。规则库中没有任何一条声称自己依据了逐字条文：全部为「由原则推导」，最高严重度因此只到「提示」。

核对方式

核对方式上，土壤地下水监测核对主要使用以下几类机械可判定的检查：多字段至少填一（1 条）、须为可解析数值（1 条）、日期不得晚于给定基准（1 条）、必填项存在性（1 条）、与阈值比较（1 条）、编号或键不得重复（1 条）。此外还有 2 类出现频次较低的检查方式。

整个核对是封闭的：只看材料里写了什么，不去查任何外部数据源，也不让模型发表意见。这意味着结果可复现，也意味着无法核对材料之外的事实。

它不作什么判断

本族插件的共同约定是：只列出材料内部可以逐条指认的差异，不判定合规、不认定责任、不替代主管部门或审核人的结论。报告里每一条差异都会带上它对照的规则、依据的文件与条款，以及差异的具体位置。

本插件不产生「错误」级结果，严重度最高为「提示」。它指出的是「此处与依据不一致」，而不是「此处是错的」。

规则库中未被命中的规则同样会出现在结果里：无法执行的检查会连同原因一起列出，空的结果列表不等于材料没有问题，只等于规则库覆盖到的那部分没有发现差异。

结果怎么读

本插件共 8 条规则，其中严重度最高的一档是「提示」，共 8 条：SW-001、SW-002、SW-003、SW-004、SW-005、SW-006、SW-007、SW-008。结果里先看这几条，再回头处理其他规则报出的差异。

适用场景与同组插件

面向施工、监理与建设单位的现场与报批文件核对：安全技术交底、监理日志、危大工程、环评导则、土壤与地下水监测。

同一职业分组「工程建设」下还有 6 个核查插件，分别是环评导则核对（dsh-eia-guide-check）、防护用品配置核对（dsh-guard-plan-qc）、HAZOP 分析表核对（dsh-hazplan-check）、许可办理核对（dsh-permit-report-check）、安全技术交底核对（dsh-safety-brief-check）、监理日志校验（dsh-site-log-check）。这几个插件的范围彼此不重叠，也不会互相替代；要覆盖这类材料的全貌，需要挑出对应的几个分别跑。

安装

先在 bash 或 PowerShell 里装上，再确认配置里出现了这个包名：

bash / sh

dsh plugin --profile default add dsh-soilwater-check
dsh --profile default --dump-config | grep 'dsh-soilwater-check'

PowerShell

dsh plugin --profile default add dsh-soilwater-check
dsh --profile default --dump-config | Select-String 'dsh-soilwater-check'

把 --profile default 换成实际使用的 profile 名。装上之后重新启动会话，插件注册的工具才会出现。
