这个插件核对什么

决策程序核对（dsh-soe-decision-check）是一个面向国企治理场景的 DeepSeek Harness 核查插件。三重一大决策台账核对（按前置研究、会议审议与决议记录核对程序留痕，仅提示差异，不作出定性结论）

8 条规则，是本族里最常见的一档规模，大体对应一次认真的人工通读能看住的范围。规则库中没有任何一条声称自己依据了逐字条文：全部为「由原则推导」，最高严重度因此只到「提示」。

核对方式

核对方式上，决策程序核对主要使用以下几类机械可判定的检查：条件必填（2 条）、多字段至少填一（1 条）、日期可解析（1 条）、必填项存在性（1 条）、取值须在允许清单内（1 条）、表头要素存在性（1 条）。此外还有 1 类出现频次较低的检查方式。

所有检查都只在材料内部完成——不连外部数据库、不联网、不请模型裁决，所以同一份材料在相同配置下重复跑，结果逐字相同。

需要说明的是，该规则库不做任何数值运算，核对的是要素是否齐备、取值是否在允许范围内、字段之间的关系是否自洽。

它不作什么判断

把它当成一次机械的交叉核对，而不是一次评审。核对结果里不会出现「合规」「不合格」这类字样，只有「此处与所引依据不一致」以及不一致的具体位置。

本插件不使用「错误」级严重度，最高只到「提示」：所有规则都只说明「这里与依据不一致」，是否构成问题由人工判断。

规则库中未被命中的规则同样会出现在结果里：无法执行的检查会连同原因一起列出，空的结果列表不等于材料没有问题，只等于规则库覆盖到的那部分没有发现差异。

依据类型含义：由原则推导（8 条）——未能取得逐字条文，依原则性条款推导，严重度上限为「提示」。

引用取证状态

引用取证：这套规则库没有一条规则声称直接对照逐字条文——8 条规则全部属于「由原则推导」或「本机构配置」。因此也没有「条文未取得」的欠账需要标注：从一开始就没有引用条文原文。结果中的差异是原则层面的一致性提示。

规则库落在 1 份文件上，分布如下：《关于进一步推进国有企业贯彻落实"三重一大"决策制度的意见》（8 条）。同一文件的不同条款会被多条规则分别引用，因此上面是文件层面的汇总。

结果怎么读

本插件共 8 条规则，其中严重度最高的一档是「提示」，共 7 条：SD-001、SD-002、SD-003、SD-004、SD-005、SD-007、SD-008。这些规则命中时应当优先处理，其余规则的结果可以在其后逐条确认。

适用场景与同组插件

面向国有企业治理与内控岗的程序留痕核对：三重一大决策台账、作业规程与 FMEA／控制计划的一致性。

同一职业分组「国企治理」下还有 1 个核查插件，分别是规程同步核对（dsh-sop-sync-check）。实际使用中往往要跑不止一个：单个插件只负责它自己那份规则库声明过的范围，范围之间不重叠，合起来才接近一次完整复核。

npm 包名 dsh-soe-decision-check，仓库 PerryLink/dsh-soe-decision-check，Apache-2.0 许可。页面上的规则与依据由构建脚本从规则库（版本 2026.1）与包的 locale 资源读出，与仓库内容一致。

  • 规程同步核对 dsh-sop-sync-check —— 作业规程与 FMEA／控制计划一致性核对

安装

插件通过 dsh plugin add 安装，两条命令的主体一致，区别只在装完后用什么方式确认它已经注册：

bash / sh

dsh plugin --profile default add dsh-soe-decision-check
dsh --profile default --dump-config | grep 'dsh-soe-decision-check'

PowerShell

dsh plugin --profile default add dsh-soe-decision-check
dsh --profile default --dump-config | Select-String 'dsh-soe-decision-check'

profile 名按实际情况替换。注意安装本身不会热加载——重开会话之后插件才生效。
