这个插件核对什么

诉状要素核对（dsh-pleading-draft）是一个面向法律诉讼场景的 DeepSeek Harness 核查插件。起诉状要素齐备性核对（按诉请、事实、证据、法条四要素核对文书齐备，仅提示差异，不作出定性结论）

规则库 7 条规则，数量居中：既能覆盖这类材料的主要要素，又不会把无关项也拉进来。该规则库同时包含「条文直接规定」与「由原则推导」两类依据：前者 4 条，后者 3 条。

核对方式

诉状要素核对的检查手段集中在以下几类，都不依赖模型判断：必填项存在性（3 条）、条件必填（1 条）、表头要素存在性（1 条）、编号或键不得重复（1 条）、须包含给定要素之一（1 条）。

整个核对是封闭的：只看材料里写了什么，不去查任何外部数据源，也不让模型发表意见。这意味着结果可复现，也意味着无法核对材料之外的事实。

这里没有算术核对——规则库处理的是齐备性、取值合法性与字段关系，不重算任何金额或数量。

它不作什么判断

这一族插件的立场一致：把材料内部能够逐条指认的差异列出来，合规与否、责任归属、以及能否通过审核，都不由插件给出。每条差异都附上它对照的规则、依据的文件与条款和差异位置，便于逐个复核。

本插件不使用「错误」级严重度，最高只到「提示」：所有规则都只说明「这里与依据不一致」，是否构成问题由人工判断。

没被命中的规则不会被悄悄丢掉：凡是没能执行的检查都会连同原因一并列出。因此结果为空只说明规则库覆盖到的范围内没发现差异，不能读成「材料没问题」。

严重度含义：提示（7 条）——差异成立，但条文未直接规定，或需人工判断后确认。

依据类型含义：条文直接规定（4 条）——该规则的依据条文已取得逐字文本，规则直接对照条文规定；由原则推导（3 条）——未能取得逐字条文，依原则性条款推导，严重度上限为「提示」。

这是插件声明的依据清单。要注意它是文件层面的：每条规则实际对照的是文件中的某个具体条款，取证进度按条款记录。

引用取证状态

引用取证：可以逐字对照条文的规则共 4 条，没有一条规则标注「本次未取得」。这意味着规则库对自身依据的声明是完整的：要么引用条文原文，要么明确说明依据并非条文。

规则库合计引用 1 份文件，引用规则数依次为：《中华人民共和国民事诉讼法》（7 条）。同一文件的不同条款会被多条规则分别引用，因此上面是文件层面的汇总。

结果怎么读

本插件共 7 条规则，其中严重度最高的一档是「提示」，共 7 条：PL-001、PL-002、PL-003、PL-004、PL-005、PL-006、PL-007。这几条是清单里最需要先看的；其余条目按材料实际内容逐条判断即可。

适用场景与同组插件

面向律师与法务的诉讼文书核对：起诉状四要素、证据清单齐备性、法条引用与文书要素的可核验性。

同一职业分组「法律诉讼」下还有 2 个核查插件，分别是证据清单核对（dsh-evidence-check）、法条引用核对（dsh-lawcite-adapter）。这几个插件的范围彼此不重叠，也不会互相替代；要覆盖这类材料的全貌，需要挑出对应的几个分别跑。

该插件以 npm 包 dsh-pleading-draft 发布，仓库在 GitHub 的 PerryLink/dsh-pleading-draft，采用 Apache-2.0 许可。本页内容由构建脚本从插件自身的规则库与 locale 资源生成，与仓库中的规则库版本 2026.1 对应。

  • 证据清单核对 dsh-evidence-check —— 证据清单齐备性核对
  • 法条引用核对 dsh-lawcite-adapter —— 法条引用与文书要素核对

安装

安装分两步——先 add，再确认它进了配置。两条命令都与平台无关，只有过滤输出的写法不同：

bash / sh

dsh plugin --profile default add dsh-pleading-draft
dsh --profile default --dump-config | grep 'dsh-pleading-draft'

PowerShell

dsh plugin --profile default add dsh-pleading-draft
dsh --profile default --dump-config | Select-String 'dsh-pleading-draft'

若你用的不是 default profile，把名字替换掉即可。安装后需要重启会话，工具才会注册进来。
