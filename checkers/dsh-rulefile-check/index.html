这个插件核对什么

规则库自检（dsh-rulefile-check）是一个面向招投标场景的 DeepSeek Harness 核查插件。规则库文件自检核对（按条款引用纪律与效力上限核对规则库自身合规，仅提示差异，不作出定性结论）

规则库 7 条规则，数量居中：既能覆盖这类材料的主要要素，又不会把无关项也拉进来。规则库中没有任何一条声称自己依据了逐字条文：全部为「由原则推导」，最高严重度因此只到「提示」。

核对方式

核对方式上，规则库自检主要使用以下几类机械可判定的检查：编号或键不得重复（1 条）、多字段至少填一（1 条）、最小长度（1 条）、格式须匹配规定形式（1 条）、条件必填（1 条）、取值须在允许清单内（1 条）。此外还有 1 类出现频次较低的检查方式。

所有检查都只在材料内部完成——不连外部数据库、不联网、不请模型裁决，所以同一份材料在相同配置下重复跑，结果逐字相同。

这里没有算术核对——规则库处理的是齐备性、取值合法性与字段关系，不重算任何金额或数量。

它不作什么判断

这个插件不提供结论，只提供线索：材料内部可以逐条指认的不一致会被列出来，每条都标明它对照的规则、依据的文件与条款、以及差异在材料中的位置。是否构成问题、是否需要整改，由看到这份清单的人判断。

这个插件不会说某处「错了」。它最高只标到「提示」级，含义是「此处与所引依据对不上，请确认」。

规则库中未被命中的规则同样会出现在结果里：无法执行的检查会连同原因一起列出，空的结果列表不等于材料没有问题，只等于规则库覆盖到的那部分没有发现差异。

这是引用取证记录中的完整编号与效力说明，含发布日期、实施日期、代替关系与强制性说明。规则库核对时对照的是这里列出的版本；若本单位执行的是其他版本，结论不直接适用。

上表来自插件声明的 normativeBasis；规则库内部还会把每条规则落到具体条款上。条款原文的取证情况见下一节。

引用取证状态

引用取证：这套规则库没有一条规则声称直接对照逐字条文——7 条规则全部属于「由原则推导」或「本机构配置」。因此也没有「条文未取得」的欠账需要标注：从一开始就没有引用条文原文。结果中的差异是原则层面的一致性提示。

规则引用的文件共 3 份，按引用规则数排列为：本插件家族的条款引用纪律（自定纪律，非国家标准）（5 条）、本插件家族的检查引擎契约（自定纪律，非国家标准）（1 条）、本插件家族的规则库契约（自定纪律，非国家标准）（1 条）。引用数统计到文件一层；同一文件内的不同条款可能分别支撑不同规则。

结果怎么读

本插件共 7 条规则，其中严重度最高的一档是「提示」，共 7 条：RF-001、RF-002、RF-003、RF-004、RF-005、RF-006、RF-007。这几条是清单里最需要先看的；其余条目按材料实际内容逐条判断即可。

适用场景与同组插件

面向招标人、招标代理与投标人的文件级核对：投标文件符合性、投标人资格、评标因素评分矩阵、质疑与投诉期限。

同一职业分组「招投标」下还有 6 个核查插件，分别是投标符合性预检（dsh-bid-ca-precheck）、资格条件核对（dsh-bid-qual-check）、合同立场核对（dsh-contract-stance）、质疑投诉期限核对（dsh-protest-deadline）、招标条款摘录核对（dsh-tender-extract）、评分矩阵核对（dsh-tender-matrix）。这几个插件的范围彼此不重叠，也不会互相替代；要覆盖这类材料的全貌，需要挑出对应的几个分别跑。

该插件以 npm 包 dsh-rulefile-check 发布，仓库在 GitHub 的 PerryLink/dsh-rulefile-check，采用 Apache-2.0 许可。本页内容由构建脚本从插件自身的规则库与 locale 资源生成，与仓库中的规则库版本 2026.1 对应。

  • 投标符合性预检 dsh-bid-ca-precheck —— 投标文件符合性预检
  • 资格条件核对 dsh-bid-qual-check —— 投标人资格条件核对
  • 合同立场核对 dsh-contract-stance —— 合同条款立场台账核对
  • 质疑投诉期限核对 dsh-protest-deadline —— 质疑与投诉期限核对
  • 招标条款摘录核对 dsh-tender-extract —— 招标文件条款摘录核对
  • 评分矩阵核对 dsh-tender-matrix —— 评标因素评分矩阵核对

安装

先在 bash 或 PowerShell 里装上，再确认配置里出现了这个包名：

bash / sh

dsh plugin --profile default add dsh-rulefile-check
dsh --profile default --dump-config | grep 'dsh-rulefile-check'

PowerShell

dsh plugin --profile default add dsh-rulefile-check
dsh --profile default --dump-config | Select-String 'dsh-rulefile-check'

把 --profile default 换成实际使用的 profile 名。装上之后重新启动会话，插件注册的工具才会出现。
