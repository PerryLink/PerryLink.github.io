这个插件核对什么

安全技术交底核对（dsh-safety-brief-check）是一个面向工程建设场景的 DeepSeek Harness 核查插件。安全技术交底记录要素齐备性与签字闭环核对（依据公开的安全生产法规与检查标准，仅提示差异，不作出定性结论）

规则库共 7 条规则，覆盖面与人工复核一遍的注意力分配大致相当。该规则库同时包含「条文直接规定」与「由原则推导」两类依据：前者 2 条，后者 4 条，另有 1 条取自使用机构自身配置。

核对方式

安全技术交底核对的检查手段集中在以下几类，都不依赖模型判断：。

整个核对是封闭的：只看材料里写了什么，不去查任何外部数据源，也不让模型发表意见。这意味着结果可复现，也意味着无法核对材料之外的事实。

这里没有算术核对——规则库处理的是齐备性、取值合法性与字段关系，不重算任何金额或数量。

它不作什么判断

本族插件的共同约定是：只列出材料内部可以逐条指认的差异，不判定合规、不认定责任、不替代主管部门或审核人的结论。报告里每一条差异都会带上它对照的规则、依据的文件与条款，以及差异的具体位置。

与其他插件不同，本插件会给出「错误」级结果：1 条规则属于该级。这一级只在规则所依据的条文已取得逐字文本时使用，命中即表示材料与条文明确不符。

需要注意 1 条「本机构配置」类规则：它们的阈值与清单由使用机构自己填入，插件不自带。配置为空时这些规则不会执行，而是把自己列进跳过项。

每个没能跑起来的检查都会出现在跳过项里并附上原因——缺字段、缺配置、或规则要求的前置项不存在。所以「没有差异」和「没有检查」在结果里是两件分开陈述的事。

SB-007交底内容应体现危险因素、操作规程与应急措施提示由原则推导

严重度含义：错误（1 条）——规则所依据的条文已取得逐字文本，出现差异即为明确不符；提示（5 条）——差异成立，但条文未直接规定，或需人工判断后确认；参考（1 条）——只作提示，供人工复核，不构成任何结论。

依据类型含义：本机构配置（1 条）——阈值或清单来自使用机构自身配置而非国家标准，严重度上限为「参考」；条文直接规定（2 条）——该规则的依据条文已取得逐字文本，规则直接对照条文规定；由原则推导（4 条）——未能取得逐字条文，依原则性条款推导，严重度上限为「提示」。

引用取证状态

引用取证：可以逐字对照条文的规则共 2 条，没有一条规则标注「本次未取得」。这意味着规则库对自身依据的声明是完整的：要么引用条文原文，要么明确说明依据并非条文。

规则库落在 3 份文件上，分布如下：《建筑施工安全技术统一规范》（3 条）、《建设工程安全生产管理条例》（2 条）、《建筑施工安全检查标准》（2 条）。引用数统计到文件一层；同一文件内的不同条款可能分别支撑不同规则。

结果怎么读

本插件共 7 条规则，其中严重度最高的一档是「错误」，共 1 条：SB-002。这几条是清单里最需要先看的；其余条目按材料实际内容逐条判断即可。

还有 1 条规则属于「本机构配置」（SB-001）。使用前请确认这几条的配置与本机构口径一致，否则核对的是别人的标准。

适用场景与同组插件

面向施工、监理与建设单位的现场与报批文件核对：安全技术交底、监理日志、危大工程、环评导则、土壤与地下水监测。

同一职业分组「工程建设」下还有 6 个核查插件，分别是环评导则核对（dsh-eia-guide-check）、防护用品配置核对（dsh-guard-plan-qc）、HAZOP 分析表核对（dsh-hazplan-check）、许可办理核对（dsh-permit-report-check）、监理日志校验（dsh-site-log-check）、土壤地下水监测核对（dsh-soilwater-check）。实际使用中往往要跑不止一个：单个插件只负责它自己那份规则库声明过的范围，范围之间不重叠，合起来才接近一次完整复核。

安装

安装分两步——先 add，再确认它进了配置。两条命令都与平台无关，只有过滤输出的写法不同：

bash / sh

dsh plugin --profile default add dsh-safety-brief-check
dsh --profile default --dump-config | grep 'dsh-safety-brief-check'

PowerShell

dsh plugin --profile default add dsh-safety-brief-check
dsh --profile default --dump-config | Select-String 'dsh-safety-brief-check'

上面的 default 是占位，换成你自己的 profile。确认配置里能搜到包名，再重开会话使用。
