这个插件核对什么

评分矩阵核对（dsh-tender-matrix）是一个面向招投标场景的 DeepSeek Harness 核查插件。评标因素评分矩阵核对（按分值上限与合计核对矩阵自洽，仅提示差异，不作出定性结论）

7 条规则，是本族里最常见的一档规模，大体对应一次认真的人工通读能看住的范围。这 7 条规则里，1 条有逐字条文支撑，5 条只能由原则推导，1 条的依据是本机构配置。

核对方式

从检查方式看，评分矩阵核对用的是几类可以机械判定的手段：。

这些检查都只读取材料本身的内容：不查外部数据库、不做联网核对、不调用模型判断，因此同一份材料在同样配置下每次得到的结果一致。

该规则库不涉及数值计算：它看的是要素齐不齐、取值在不在允许范围内、字段之间对不对得上。

它不作什么判断

共同约定只有一条——插件只做「指出不一致」，不做「下结论」。差异清单里每条都带规则编号、依据的文件与条款、以及差异落在材料里的位置。

本插件不产生「错误」级结果，严重度最高为「提示」。它指出的是「此处与依据不一致」，而不是「此处是错的」。

需要注意 1 条「本机构配置」类规则：它们的阈值与清单由使用机构自己填入，插件不自带。配置为空时这些规则不会执行，而是把自己列进跳过项。

没被命中的规则不会被悄悄丢掉：凡是没能执行的检查都会连同原因一并列出。因此结果为空只说明规则库覆盖到的范围内没发现差异，不能读成「材料没问题」。

严重度含义：提示（6 条）——差异成立，但条文未直接规定，或需人工判断后确认；参考（1 条）——只作提示，供人工复核，不构成任何结论。

依据类型含义：由原则推导（5 条）——未能取得逐字条文，依原则性条款推导，严重度上限为「提示」；条文直接规定（1 条）——该规则的依据条文已取得逐字文本，规则直接对照条文规定；本机构配置（1 条）——阈值或清单来自使用机构自身配置而非国家标准，严重度上限为「参考」。

结果怎么读

本插件共 7 条规则，其中严重度最高的一档是「提示」，共 6 条：TM-001、TM-002、TM-004、TM-005、TM-006、TM-007。结果里先看这几条，再回头处理其他规则报出的差异。

还有 1 条规则属于「本机构配置」（TM-003）。这几条只有在配置被填写后才会执行；未配置时它们不会静默通过，而是列入跳过。

适用场景与同组插件

面向招标人、招标代理与投标人的文件级核对：投标文件符合性、投标人资格、评标因素评分矩阵、质疑与投诉期限。

同一职业分组「招投标」下还有 6 个核查插件，分别是投标符合性预检（dsh-bid-ca-precheck）、资格条件核对（dsh-bid-qual-check）、合同立场核对（dsh-contract-stance）、质疑投诉期限核对（dsh-protest-deadline）、规则库自检（dsh-rulefile-check）、招标条款摘录核对（dsh-tender-extract）。这类材料通常需要同时过几个插件：一个插件只覆盖它自己那份规则库声明过的范围，把几个插件的结果合起来看才是完整的一次复核。

该插件以 npm 包 dsh-tender-matrix 发布，仓库在 GitHub 的 PerryLink/dsh-tender-matrix，采用 Apache-2.0 许可。本页内容由构建脚本从插件自身的规则库与 locale 资源生成，与仓库中的规则库版本 2026.1 对应。

  • 投标符合性预检 dsh-bid-ca-precheck —— 投标文件符合性预检
  • 资格条件核对 dsh-bid-qual-check —— 投标人资格条件核对
  • 合同立场核对 dsh-contract-stance —— 合同条款立场台账核对
  • 质疑投诉期限核对 dsh-protest-deadline —— 质疑与投诉期限核对
  • 规则库自检 dsh-rulefile-check —— 规则库文件自检核对
  • 招标条款摘录核对 dsh-tender-extract —— 招标文件条款摘录核对

安装

插件通过 dsh plugin add 安装，两条命令的主体一致，区别只在装完后用什么方式确认它已经注册：

bash / sh

dsh plugin --profile default add dsh-tender-matrix
dsh --profile default --dump-config | grep 'dsh-tender-matrix'

PowerShell

dsh plugin --profile default add dsh-tender-matrix
dsh --profile default --dump-config | Select-String 'dsh-tender-matrix'

上面的 default 是占位，换成你自己的 profile。确认配置里能搜到包名，再重开会话使用。
