这个插件核对什么

公文流转核对（dsh-gongwen-flow-check）是一个面向公文档案场景的 DeepSeek Harness 核查插件。公文流转与办理时限核对（按公开的公文处理规范核对环节完整性与时限，仅提示差异，不作出定性结论）

6 条规则构成了它的全部核对范围，规则数量在本族中偏少，换来的是每条规则都足够具体。该规则库的规则依据构成为：由原则推导 4 条、本机构配置 2 条。

核对方式

从检查方式看，公文流转核对用的是几类可以机械判定的手段：。

整个核对是封闭的：只看材料里写了什么，不去查任何外部数据源，也不让模型发表意见。这意味着结果可复现，也意味着无法核对材料之外的事实。

该规则库不涉及数值计算：它看的是要素齐不齐、取值在不在允许范围内、字段之间对不对得上。

它不作什么判断

本族插件的共同约定是：只列出材料内部可以逐条指认的差异，不判定合规、不认定责任、不替代主管部门或审核人的结论。报告里每一条差异都会带上它对照的规则、依据的文件与条款，以及差异的具体位置。

本插件不产生「错误」级结果，严重度最高为「提示」。它指出的是「此处与依据不一致」，而不是「此处是错的」。

其中 2 条规则的阈值或清单来自使用机构自身配置，而不是国家标准。这类规则在更换机构后必须先改配置再使用，否则会拿别的机构的口径核对本机构的材料。

没被命中的规则不会被悄悄丢掉：凡是没能执行的检查都会连同原因一并列出。因此结果为空只说明规则库覆盖到的范围内没发现差异，不能读成「材料没问题」。

严重度含义：提示（4 条）——差异成立，但条文未直接规定，或需人工判断后确认；参考（2 条）——只作提示，供人工复核，不构成任何结论。

依据类型含义：由原则推导（4 条）——未能取得逐字条文，依原则性条款推导，严重度上限为「提示」；本机构配置（2 条）——阈值或清单来自使用机构自身配置而非国家标准，严重度上限为「参考」。

引用取证状态

引用取证：这套规则库没有一条规则声称直接对照逐字条文——6 条规则全部属于「由原则推导」或「本机构配置」。因此也没有「条文未取得」的欠账需要标注：从一开始就没有引用条文原文。结果中的差异是原则层面的一致性提示。

规则库落在 1 份文件上，分布如下：《党政机关公文处理工作条例》（6 条）。同一文件的不同条款会被多条规则分别引用，因此上面是文件层面的汇总。

结果怎么读

本插件共 6 条规则，其中严重度最高的一档是「提示」，共 4 条：GF-001、GF-002、GF-005、GF-006。结果里先看这几条，再回头处理其他规则报出的差异。

还有 2 条规则属于「本机构配置」（GF-003、GF-004）。它们的判据来自配置项而不是国家标准，配置未填时这几条会进入跳过项。

适用场景与同组插件

面向办公室、文秘与档案室的公文与归档核对：公文格式要素、文种与发文字号、流转时限、归档完整性与保管期限。

同一职业分组「公文档案」下还有 2 个核查插件，分别是档案归档核对（dsh-archive-check）、公文格式核对（dsh-gongwen-word-check）。这几个插件的范围彼此不重叠，也不会互相替代；要覆盖这类材料的全貌，需要挑出对应的几个分别跑。

npm 包名 dsh-gongwen-flow-check，仓库 PerryLink/dsh-gongwen-flow-check，Apache-2.0 许可。页面上的规则与依据由构建脚本从规则库（版本 2026.1）与包的 locale 资源读出，与仓库内容一致。

  • 档案归档核对 dsh-archive-check —— 档案归档完整性与保管期限核对
  • 公文格式核对 dsh-gongwen-word-check —— 公文格式要素核对

安装

安装命令对两个平台是同一个 dsh 子命令，只有随后确认安装结果的那一步按 shell 不同：

bash / sh

dsh plugin --profile default add dsh-gongwen-flow-check
dsh --profile default --dump-config | grep 'dsh-gongwen-flow-check'

PowerShell

dsh plugin --profile default add dsh-gongwen-flow-check
dsh --profile default --dump-config | Select-String 'dsh-gongwen-flow-check'

把 --profile default 换成实际使用的 profile 名。装上之后重新启动会话，插件注册的工具才会出现。
