这个插件核对什么

防护用品配置核对（dsh-guard-plan-qc）是一个面向工程建设场景的 DeepSeek Harness 核查插件。劳动保护与安全防护用品配置表核对（按公开的配备标准核对品名规格与配置数量，仅提示差异，不作出定性结论）

规则库只有 6 条规则，是本族里最精简的一档；它不追求把材料过一遍，只盯住这类材料上最容易出错的地方。该规则库的规则依据构成为：本机构配置 3 条、由原则推导 3 条。

核对方式

防护用品配置核对的检查手段集中在以下几类，都不依赖模型判断：。

所有检查都只在材料内部完成——不连外部数据库、不联网、不请模型裁决，所以同一份材料在相同配置下重复跑，结果逐字相同。

这里没有算术核对——规则库处理的是齐备性、取值合法性与字段关系，不重算任何金额或数量。

它不作什么判断

把它当成一次机械的交叉核对，而不是一次评审。核对结果里不会出现「合规」「不合格」这类字样，只有「此处与所引依据不一致」以及不一致的具体位置。

结果里最高的严重度是「提示」。这不是保守，而是如实的：这些规则所对照的条文没有逐字文本，凭原则推导不足以支撑更强的结论。

其中 3 条规则的阈值或清单来自使用机构自身配置，而不是国家标准。这类规则在更换机构后必须先改配置再使用，否则会拿别的机构的口径核对本机构的材料。

每个没能跑起来的检查都会出现在跳过项里并附上原因——缺字段、缺配置、或规则要求的前置项不存在。所以「没有差异」和「没有检查」在结果里是两件分开陈述的事。

严重度含义：提示（3 条）——差异成立，但条文未直接规定，或需人工判断后确认；参考（3 条）——只作提示，供人工复核，不构成任何结论。

依据类型含义：本机构配置（3 条）——阈值或清单来自使用机构自身配置而非国家标准，严重度上限为「参考」；由原则推导（3 条）——未能取得逐字条文，依原则性条款推导，严重度上限为「提示」。

引用取证状态

引用取证：这套规则库没有任何一条规则可以直接对照逐字条文，全部属于「由原则推导」；其中 6 条在规则库中明确写着条文本次未取得，其余 0 条同样没有条文比对，只是未标记取证状态。

规则库合计引用 1 份文件，引用规则数依次为：《个体防护装备配备规范》（6 条）。引用数统计到文件一层；同一文件内的不同条款可能分别支撑不同规则。

结果怎么读

本插件共 6 条规则，其中严重度最高的一档是「提示」，共 3 条：GP-002、GP-004、GP-005。这些规则命中时应当优先处理，其余规则的结果可以在其后逐条确认。

另有 6 条规则的条文本次未取得逐字文本（GP-001、GP-002、GP-003、GP-004、GP-005、GP-006）。引用这部分结果时请注意措辞：它们是原则推导的产物，不是条文比对的结果。

还有 3 条规则属于「本机构配置」（GP-001、GP-003、GP-006）。这几条只有在配置被填写后才会执行；未配置时它们不会静默通过，而是列入跳过。

适用场景与同组插件

面向施工、监理与建设单位的现场与报批文件核对：安全技术交底、监理日志、危大工程、环评导则、土壤与地下水监测。

同一职业分组「工程建设」下还有 6 个核查插件，分别是环评导则核对（dsh-eia-guide-check）、HAZOP 分析表核对（dsh-hazplan-check）、许可办理核对（dsh-permit-report-check）、安全技术交底核对（dsh-safety-brief-check）、监理日志校验（dsh-site-log-check）、土壤地下水监测核对（dsh-soilwater-check）。这类材料通常需要同时过几个插件：一个插件只覆盖它自己那份规则库声明过的范围，把几个插件的结果合起来看才是完整的一次复核。

发布渠道是 npm 包 dsh-guard-plan-qc，源码在 GitHub 的 PerryLink/dsh-guard-plan-qc，许可为 Apache-2.0。本页的规则清单直接取自仓库里的规则库文件（版本 2026.1），不是手写的介绍。

  • 环评导则核对 dsh-eia-guide-check —— 环评导则适用性核对
  • HAZOP 分析表核对 dsh-hazplan-check —— HAZOP 分析表要素齐备性与偏差推导一致性核对
  • 许可办理核对 dsh-permit-report-check —— 行政许可办理核对
  • 安全技术交底核对 dsh-safety-brief-check —— 安全技术交底记录要素齐备性与签字闭环核对
  • 监理日志校验 dsh-site-log-check —— 监理日志跨日连续性与旁站覆盖提示
  • 土壤地下水监测核对 dsh-soilwater-check —— 土壤与地下水监测台账核对

安装

安装命令对两个平台是同一个 dsh 子命令，只有随后确认安装结果的那一步按 shell 不同：

bash / sh

dsh plugin --profile default add dsh-guard-plan-qc
dsh --profile default --dump-config | grep 'dsh-guard-plan-qc'

PowerShell

dsh plugin --profile default add dsh-guard-plan-qc
dsh --profile default --dump-config | Select-String 'dsh-guard-plan-qc'

若你用的不是 default profile，把名字替换掉即可。安装后需要重启会话，工具才会注册进来。
