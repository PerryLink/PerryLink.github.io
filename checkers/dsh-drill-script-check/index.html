这个插件核对什么

演练脚本核对（dsh-drill-script-check）是一个面向安全生产场景的 DeepSeek Harness 核查插件。应急演练脚本核对（按阶段、响应分级、指挥与资源要素核对脚本齐备，仅提示差异，不作出定性结论）

规则库 8 条规则，数量居中：既能覆盖这类材料的主要要素，又不会把无关项也拉进来。按依据类型拆开看：由原则推导 7 条、本机构配置 1 条。

核对方式

核对方式上，演练脚本核对主要使用以下几类机械可判定的检查：必填项存在性（2 条）、多字段至少填一（1 条）、取值须在允许清单内（1 条）、条件必填（1 条）、求和结果一致（1 条）、编号或键不得重复（1 条）。此外还有 1 类出现频次较低的检查方式。

检查过程不引入任何外部信息：没有数据库查询、没有网络请求、没有模型参与，同样输入必然得到同样输出。

它不作什么判断

把它当成一次机械的交叉核对，而不是一次评审。核对结果里不会出现「合规」「不合格」这类字样，只有「此处与所引依据不一致」以及不一致的具体位置。

结果里最高的严重度是「提示」。这不是保守，而是如实的：这些规则所对照的条文没有逐字文本，凭原则推导不足以支撑更强的结论。

其中 1 条规则的阈值或清单来自使用机构自身配置，而不是国家标准。这类规则在更换机构后必须先改配置再使用，否则会拿别的机构的口径核对本机构的材料。

不要把空清单当成结论。规则库够不到的地方、以及因为材料缺少必要字段而无法执行的规则，都会连同原因单列；它们既不算通过，也不算失败。

严重度含义：提示（7 条）——差异成立，但条文未直接规定，或需人工判断后确认；参考（1 条）——只作提示，供人工复核，不构成任何结论。

依据类型含义：由原则推导（7 条）——未能取得逐字条文，依原则性条款推导，严重度上限为「提示」；本机构配置（1 条）——阈值或清单来自使用机构自身配置而非国家标准，严重度上限为「参考」。

结果怎么读

本插件共 8 条规则，其中严重度最高的一档是「提示」，共 7 条：DR-001、DR-002、DR-004、DR-005、DR-006、DR-007、DR-008。这几条是清单里最需要先看的；其余条目按材料实际内容逐条判断即可。

另有 8 条规则的条文本次未取得逐字文本（DR-001、DR-002、DR-003、DR-004、DR-005、DR-006、DR-007、DR-008）。这些规则报出的差异只能作为线索，不能当作「违反某条条文」来引用。

还有 1 条规则属于「本机构配置」（DR-003）。使用前请确认这几条的配置与本机构口径一致，否则核对的是别人的标准。

适用场景与同组插件

面向生产经营单位安全管理岗的台账与预案核对：危化品临界量、应急预案要素、演练脚本、隐患判定、两票与线损。

同一职业分组「安全生产」下还有 6 个核查插件，分别是养殖投入品核对（dsh-aqua-input-check）、应急预案要素校验（dsh-emergency-plan）、危化品临界量核对（dsh-hazchem-check）、重大隐患条款映射（dsh-hidden-risk-map）、线损拆分核对（dsh-power-loss-split）、电力工作票核对（dsh-power-ticket-check）。这几个插件的范围彼此不重叠，也不会互相替代；要覆盖这类材料的全貌，需要挑出对应的几个分别跑。

安装

安装分两步——先 add，再确认它进了配置。两条命令都与平台无关，只有过滤输出的写法不同：

bash / sh

dsh plugin --profile default add dsh-drill-script-check
dsh --profile default --dump-config | grep 'dsh-drill-script-check'

PowerShell

dsh plugin --profile default add dsh-drill-script-check
dsh --profile default --dump-config | Select-String 'dsh-drill-script-check'

上面的 default 是占位，换成你自己的 profile。确认配置里能搜到包名，再重开会话使用。
