这个插件核对什么

监理日志校验（dsh-site-log-check）是一个面向工程建设场景的 DeepSeek Harness 核查插件。监理日志跨日连续性与旁站覆盖提示（依据 GB/T 50319-2013 等公开文件，仅提示差异，不作出定性结论）

规则库有 14 条规则，在本族中属于覆盖面较宽的一档，适合在正式复核前先跑一遍。这 14 条规则里，13 条有逐字条文支撑，1 条只能由原则推导。

检查过程不引入任何外部信息：没有数据库查询、没有网络请求、没有模型参与，同样输入必然得到同样输出。

需要说明的是，该规则库不做任何数值运算，核对的是要素是否齐备、取值是否在允许范围内、字段之间的关系是否自洽。

它不作什么判断

把它当成一次机械的交叉核对，而不是一次评审。核对结果里不会出现「合规」「不合格」这类字样，只有「此处与所引依据不一致」以及不一致的具体位置。

本插件不使用「错误」级严重度，最高只到「提示」：所有规则都只说明「这里与依据不一致」，是否构成问题由人工判断。

不要把空清单当成结论。规则库够不到的地方、以及因为材料缺少必要字段而无法执行的规则，都会连同原因单列；它们既不算通过，也不算失败。

适用场景与同组插件

面向施工、监理与建设单位的现场与报批文件核对：安全技术交底、监理日志、危大工程、环评导则、土壤与地下水监测。

同一职业分组「工程建设」下还有 6 个核查插件，分别是环评导则核对（dsh-eia-guide-check）、防护用品配置核对（dsh-guard-plan-qc）、HAZOP 分析表核对（dsh-hazplan-check）、许可办理核对（dsh-permit-report-check）、安全技术交底核对（dsh-safety-brief-check）、土壤地下水监测核对（dsh-soilwater-check）。实际使用中往往要跑不止一个：单个插件只负责它自己那份规则库声明过的范围，范围之间不重叠，合起来才接近一次完整复核。

发布渠道是 npm 包 dsh-site-log-check，源码在 GitHub 的 PerryLink/dsh-site-log-check，许可为 Apache-2.0。本页的规则清单直接取自仓库里的规则库文件（版本 2026.1），不是手写的介绍。

  • 环评导则核对 dsh-eia-guide-check —— 环评导则适用性核对
  • 防护用品配置核对 dsh-guard-plan-qc —— 劳动保护与安全防护用品配置表核对
  • HAZOP 分析表核对 dsh-hazplan-check —— HAZOP 分析表要素齐备性与偏差推导一致性核对

  • 土壤地下水监测核对 dsh-soilwater-check —— 土壤与地下水监测台账核对

安装

安装分两步——先 add，再确认它进了配置。两条命令都与平台无关，只有过滤输出的写法不同：

bash / sh

dsh plugin --profile default add dsh-site-log-check
dsh --profile default --dump-config | grep 'dsh-site-log-check'

PowerShell

dsh plugin --profile default add dsh-site-log-check
dsh --profile default --dump-config | Select-String 'dsh-site-log-check'

把 --profile default 换成实际使用的 profile 名。装上之后重新启动会话，插件注册的工具才会出现。
