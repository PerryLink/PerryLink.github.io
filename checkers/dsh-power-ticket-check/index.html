这个插件核对什么

电力工作票核对（dsh-power-ticket-check）是一个面向安全生产场景的 DeepSeek Harness 核查插件。电力工作票要素齐备性与签发许可顺序核对（依据现行电力安全工作规程，仅提示差异，不作出定性结论）

7 条规则，是本族里最常见的一档规模，大体对应一次认真的人工通读能看住的范围。该规则库同时包含「条文直接规定」与「由原则推导」两类依据：前者 5 条，后者 1 条，另有 1 条取自使用机构自身配置。

核对方式

从检查方式看，电力工作票核对用的是几类可以机械判定的手段：。

这些检查都只读取材料本身的内容：不查外部数据库、不做联网核对、不调用模型判断，因此同一份材料在同样配置下每次得到的结果一致。

该规则库不涉及数值计算：它看的是要素齐不齐、取值在不在允许范围内、字段之间对不对得上。

它不作什么判断

共同约定只有一条——插件只做「指出不一致」，不做「下结论」。差异清单里每条都带规则编号、依据的文件与条款、以及差异落在材料里的位置。

本插件使用「错误」级严重度，共 1 条规则属于该级。这些规则所依据的条文都已取得逐字文本，只有在材料与条文明确不符时才会命中，也因此可以作为返工依据。

需要注意 1 条「本机构配置」类规则：它们的阈值与清单由使用机构自己填入，插件不自带。配置为空时这些规则不会执行，而是把自己列进跳过项。

每个没能跑起来的检查都会出现在跳过项里并附上原因——缺字段、缺配置、或规则要求的前置项不存在。所以「没有差异」和「没有检查」在结果里是两件分开陈述的事。

规则清单

规则库 power-ticket-check.yaml 的全部 7 条规则（规则库版本 2026.1）
规则检查内容严重度依据类型
PT-001工作票应填写本机构要求的栏目参考本机构配置
PT-002工作票种类应与工作性质相符提示条文直接规定
PT-003签发、许可与终结的时间先后应成立提示由原则推导
PT-004延期时间应把工作结束时间向后推提示条文直接规定
PT-005一个工作负责人不应同时执行两张及以上工作票提示条文直接规定
PT-006安全技术措施应包含停电、验电、装设接地线、悬挂标示牌、装设遮栏五项错误条文直接规定
PT-007工作许可手续应包含现场复查、指明带电部位与双方确认签名提示条文直接规定

严重度含义：错误（1 条）——规则所依据的条文已取得逐字文本，出现差异即为明确不符；提示（5 条）——差异成立，但条文未直接规定，或需人工判断后确认；参考（1 条）——只作提示，供人工复核，不构成任何结论。

依据类型含义：本机构配置（1 条）——阈值或清单来自使用机构自身配置而非国家标准，严重度上限为「参考」；条文直接规定（5 条）——该规则的依据条文已取得逐字文本，规则直接对照条文规定；由原则推导（1 条）——未能取得逐字条文，依原则性条款推导，严重度上限为「提示」。

结果怎么读

本插件共 7 条规则，其中严重度最高的一档是「错误」，共 1 条：PT-006。结果里先看这几条，再回头处理其他规则报出的差异。

还有 1 条规则属于「本机构配置」（PT-001）。使用前请确认这几条的配置与本机构口径一致，否则核对的是别人的标准。

适用场景与同组插件

面向生产经营单位安全管理岗的台账与预案核对：危化品临界量、应急预案要素、演练脚本、隐患判定、两票与线损。

同一职业分组「安全生产」下还有 6 个核查插件，分别是养殖投入品核对（dsh-aqua-input-check）、演练脚本核对（dsh-drill-script-check）、应急预案要素校验（dsh-emergency-plan）、危化品临界量核对（dsh-hazchem-check）、重大隐患条款映射（dsh-hidden-risk-map）、线损拆分核对（dsh-power-loss-split）。实际使用中往往要跑不止一个：单个插件只负责它自己那份规则库声明过的范围，范围之间不重叠，合起来才接近一次完整复核。

npm 包名 dsh-power-ticket-check，仓库 PerryLink/dsh-power-ticket-check，Apache-2.0 许可。页面上的规则与依据由构建脚本从规则库（版本 2026.1）与包的 locale 资源读出，与仓库内容一致。

  • 养殖投入品核对 dsh-aqua-input-check —— 水产养殖投入品记录核对
  • 演练脚本核对 dsh-drill-script-check —— 应急演练脚本核对
  • 应急预案要素校验 dsh-emergency-plan —— 应急预案要素齐备性与条款级页码定位
  • 危化品临界量核对 dsh-hazchem-check —— 危险化学品临界量与重大危险源辨识核对
  • 重大隐患条款映射 dsh-hidden-risk-map —— 安全隐患台账→《工贸企业重大事故隐患判定标准》
  • 线损拆分核对 dsh-power-loss-split —— 线损电量拆分与考核表核对

安装

安装命令对两个平台是同一个 dsh 子命令，只有随后确认安装结果的那一步按 shell 不同：

bash / sh

dsh plugin --profile default add dsh-power-ticket-check
dsh --profile default --dump-config | grep 'dsh-power-ticket-check'

PowerShell

dsh plugin --profile default add dsh-power-ticket-check
dsh --profile default --dump-config | Select-String 'dsh-power-ticket-check'

把 --profile default 换成实际使用的 profile 名。装上之后重新启动会话，插件注册的工具才会出现。
